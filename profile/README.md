<p>谈批发之前，几乎每个人心里都有同一串问题：批的到底是什么、怎么知道出口不重复、试用要跑多久、包月怎么起算、出了事找谁。这五个问题不解决，签下来的合同多半要在执行阶段补窟窿。这篇按真问题的方式串一遍，每个问题给判断依据和踩坑表现。担心批量环境串号的，建议先拿试用号跑一轮，确认独立出口之后再谈包月，不要用价格去换确定性。</p>

<h2>一、第一个真问题：批发价批的到底是什么</h2>

<p>「批发」这个词容易让人以为买的是同一个东西的折扣，实际买的往往是「一批资源的分配权」。十个账号配套十条出口，和十个账号共用三条出口，都能叫批发，价格差一大截，效果也差一大截。</p>

<h3>先问单位：按账号还是按出口</h3>
<p>按账号计价，意味着每个账号分到一条独立出口，价格高一些但关系清晰。按出口计价，意味着你买的是通道数量，账号怎么分配自己决定，价格低但需要自己做隔离设计。两种都能用，怕的是价格按出口算、口头承诺按账号给。</p>

<h3>再问边界：共享段算不算独享</h3>
<p>有些方案会在同一段地址下切分多个端口，每个端口叫一条「独享」。这种在技术上确实是分开的，但在平台看来仍属同一段地址。要问清「独享」指的是独立地址还是独立端口，两者在批量场景下差别很大。</p>

<h3>最后问交付物：给什么凭据</h3>
<p>正规的批发会给一份清单：账号编号、出口地址、城市、运营商、认证方式、有效期。只给一个地址池让你自己分的，后续出了问题没法追溯，也没法核对谁用了哪条。</p>

<h2>二、第二个真问题：怎么确认批出去的出口不重复</h2>

<p>批量环境串号，多数不是配置出错，而是「两条出口其实是同一段地址」。这种事在纸面上看不出来，必须自己验。</p>

<h3>方法一：逐条查 ASN 与网段</h3>
<p>把清单里每条出口地址都查一遍，记录 ASN 与所在 /24 网段。同一 /24 网段内出现多条，就要警觉，尤其是在批量规模不大的时候。十条出口里有三条同段，实际隔离效果会打折。</p>

<h3>方法二：交叉验证出口指纹</h3>
<p>用两个不同来源的查询接口各查一次，比对返回的城市与运营商是否一致。单一来源有时会把地址归属标错，两个来源都一致才可信。这一步在批量验收时值得花时间。</p>

<img src="/tp.png" alt="批发前的试用核对流程：出口重复率与独立环境验证">

<p><strong>方法三：同时在线测并发。</strong>把几条出口同时挂上，各自跑一个小任务，看是否出现互相影响：一条变慢时另一条是否也慢，一条断线时另一条是否也断。同一物理资源切分出来的端口，往往在这种情况下暴露。</p>

<p><strong>先算重复率，再谈价格。</strong>十条出口里如果只有七条真正独立，实际单价要按七条算，而不是十条。这个换算一做，很多「便宜」的报价就不便宜了。把重复率写进验收标准，比事后争论有用。</p>

<h2>三、第三个真问题：试用号跑几天才算跑过</h2>

<p>试用最容易走过场：开一条，登一次，能打开就算过。这样的试用没有回答任何关键问题。有效的试用要带着明确的检查项进去。</p>

<h3>第一天：归属与连通</h3>
<p>查 ASN 是否为家宽运营商，城市是否与账号资料一致，连续二十次请求的成功率。三项都过，进入第二天。</p>

<h3>第二天：高峰与验证</h3>
<p>把测试放在当地晚上八点到十一点，观察延迟波动与是否出现额外验证。这一段是白天测不出来的，也是最容易在上线后翻车的地方。</p>

<h3>第三天：连续在线</h3>
<p>让会话挂着四到六小时不操作，看是否被踢下线。批量场景里，很多账号是长时间挂着不动的，这一项必须测。三天覆盖三个维度，比连续测七天同一个指标有用。</p>

<h2>四、第四个真问题：包月起算、扩容与减量</h2>

<p>批量采购的成本曲线不是线性的。十个账号和二十个账号，单价可能不同；月中扩容，计费方式也可能不同。这些规则要在第一批之前问清楚，否则第二批就开始扯皮。</p>

<h3>起算日：自然月还是三十天</h3>
<p>自然月起算的，月中开通常按整月收或按天折算，两种都见过。付款日起三十天的，续费日会逐月漂移。批量场景下建议统一到月初起算，方便对账。</p>

<h3>扩容：加号是否要重新配环境</h3>
<p>扩容时最怕「新增的号与环境是套模板生成的，模板里还带着旧号的痕迹」。要确认扩容是否支持干净模板，以及新增出口是否与存量出口做过重复校验。</p>

<p><strong>减量时要问清：停掉的号出口是否回收。</strong>减量时如果出口被立即回收再分配给别人，账号将来恢复使用时登录地就变了。长期运营的账号，建议保留出口一段时间，哪怕暂停计费。</p>

<h2>五、第五个真问题：出了事找谁、按什么标准算修好</h2>

<p>批量场景下，故障不是「有没有」，而是「多久恢复、影响几条」。所以售后要谈的不是态度，是流程。</p>

<h3>唯一入口与响应时限</h3>
<p>批量客户最好约定一个唯一报修入口，避免多头对接导致信息丢失。响应时限按工作时段写明，夜间如何处理也写一句。有工单系统的，历史记录本身就是证据。</p>

<h3>「修好」要有定义</h3>
<p>换了一条能连的出口不算修好。修好的标准应该是：新出口与原出口同城、同运营商、独享，且账号首登无额外验证。这三条写进约定，才不会出现「换了一条更差的线也算处理完毕」。</p>

<p><strong>批量故障的补偿口径也要谈。</strong>如果一次故障影响超过半数账号且持续超过约定时长，是否顺延有效期或按比例折算，属于可以谈的条款。这类条款平时用不上，真用上时能省掉大量争论。</p>

<h2>常见问答</h2>

<h3>批发一般能便宜多少？</h3>
<p>答：取决于规模与是否按出口计价，常见区间比单条零售低一到三成，仅供参考。但便宜的前提是每条出口仍然独立。如果为了低价接受同一段地址切分，实际单价要按有效独立出口数折算，往往并不便宜。</p>

<h3>试用号能直接转正式吗？</h3>
<p>答：多数方案可以，且建议这样做——试用的这条出口已经验证过，转正式后保持同一地址，账号的登录环境不跳变。转之前确认地址在转正后不变，且计费从转正日起算。</p>

<h3>十条出口里有两条同段，要不要退？</h3>
<p>答：看用途。做内容分发、轻度使用的，同段影响有限；做多账号独立运营的，建议要求替换成不同网段。验收时把重复率写进标准，比用了之后才发现更容易处理。</p>

<h3>包月能不能中途停？</h3>
<p>答：不同方案不一样，需要提前问清。能停的方案通常还会涉及出口是否保留，长期账号要争取保留原地址，否则恢复时登录地跳变，省下的钱可能不够弥补。</p>
